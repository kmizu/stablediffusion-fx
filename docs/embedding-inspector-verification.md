## Source-scope audit and implementation

The native tab and serial worker implement inspection of vocabulary and textual-inversion vectors, per-vector nearest cosine scores, magnitude/min/max, a graph, vector export, tokenizer and send-to-mixer, weighted mixing, concatenation, combine-as-one, zero-row removal, save/overwrite, training-step metadata, arbitrary Python eval, eight eval presets, batch preset saves and post-save reload. Eval uses existing `SDFX_ALLOW_CODE`; it is arbitrary Python, not a sandbox, and failed permitted expressions retain the original vectors with a warning. SDXL holds `clip_l` and `clip_g` separately, retains a position if either encoder is nonzero, and requires paired numeric IDs. `.pt` and safetensors are supported; `.pt` stores step as data and safetensors as metadata. Training continuation and interoperability with an actual A1111 installation are not verified.

NUI lazily loads textual inversions, unlike upstream's embedding database. The current list explicitly separates loaded embeddings from catalog-only names, shows per-encoder vector count/width, and shows available file metadata only when the file identity still matches the loaded snapshot. Inspection reports shape and prefers recorded live loaded rows to a potentially changed catalog file. Recorded token ownership prevents unrelated names such as `concept` and `concept_1` from being combined or unloaded; unknown ambiguous ownership fails explicitly. Files and text exports are readable even under image scrambling; eval can write arbitrary files. The graph shows up to 16 vectors per selected encoder. The mini-tokenizer displays/sends at most 128 tokens, with a warning when truncated; unequal SDXL token counts require explicit mixer inputs. Save/export claims its publication boundary before mixing/eval, so cancellation can be too late even before a file exists. A batch may retain earlier successfully published files if a later write fails; no global rollback is claimed. Numeric suffix collisions are rejected conservatively rather than risking existing tokens.

Upstream explicitly covers SD1 and SD2. This implementation also supports paired SDXL, but **actual SD2 checkpoint/model behavior has not been tested**. A limited source and test review cannot establish equivalence for every expression, embedding format, tokenizer, model, or training workflow. Full independent review and broad tests are pending.
