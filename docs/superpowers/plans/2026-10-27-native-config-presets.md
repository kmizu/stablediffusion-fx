# Native Config Presets and Preset Utilities Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the complete native configuration-preset workflows of index 30 and 31 with faithful separate/shared collections, source compatibility diagnostics and no generation side effects.

**Architecture:** A pure Scala typed document/store/overlay layer serves two distinct native profiles through a shared JavaFX pane. Capture actual GenerationVM and PluginsVM properties, apply only planned field mutations, and preserve engine submission semantics, with the scoped Task 2B immutable UI variation flag in diagnostic context. Source codecs preserve unresolved fields and exact scalar values rather than treating arbitrary Gradio IDs as native controls.

**Tech Stack:** Scala 3.3.6, Java 21, JavaFX 21.0.6, upickle 4.1.0, MUnit 1.1.1, existing JDK filesystem APIs; no new library, Python hook or provider/network dependency.

**Spec:** `docs/superpowers/specs/2026-10-27-native-config-presets-design.md`; full source audit `D:/stable-diffusion-webui-reForge/stablediffusion-fx/outputs/next-core-presets-audit.md` and manifest/source directory beside it; supplemental field inventory `D:/stable-diffusion-webui-reForge/stablediffusion-fx/outputs/native-config-presets-field-map.md`. ## Global Constraints

- Design base is `89bd3ba47f70bee2ca4bea4fb9742037fbd51e03`; this plan is not implementation approval, execution evidence or a promotion.
- Root alone runs sbt/native/GPU. At most two sbt jobs with distinct output trees; exactly one native UI/GPU run at a time.
- No capture/apply calls plugin.process, script.run, JobBuilder.build, Support.fixSeed, Python, torch, model loading, inference, model downloads, hardware queries, or engine startup.
- Quicksettings checkpoint/VAE/clip skip are not exposed by either profile in this wave; no ExtendedStyle/model-loading path is reused.
- Config collections map Txt2Img -> config-txt2img, Img2Img/Inpaint -> config-img2img; apply targets only the invoking mode. Utilities shares one collection across all three.
- Non-stackable resets only available tracked fields to declared component defaults; nontracked fields, other modes and shared model fields stay intact.
- Hires scale minimum1, maximum5, step0.05; Task3B changes only the native hires widget upper bound and matching schema. Preserve all existing kernel/GenerationParams/Python/pixel-budget/resource guards.
- Source Extra is a real variation gate, not pane visibility. Native variationEnabled defaults true for backward compatibility; its source-profile default is false. Preserve raw subseed/strength drafts; only effective submitted strength becomes zero while disabled.
- Task 2B may append immutable SubmittedPayloadContext.uiVariationEnabled=None, freeze it in JobBuilder, and expose it in PayloadCaptureContext diagnostics under existing budgets. Keep extras_requested's native-params inference separate. No GenerationParams/body/protocol/Generator/kernel/RNG/Python change.
- Variation gate controls/submission apply to all three modes; current native variation image effect is txt2img only. Img2Img/Inpaint parameter parity must not be reported as kernel-effect evidence.
- Per file 4,194,304 UTF-8 bytes; max JSON nesting 32; max lexical nodes including keys 100,000; max collections 3; max records 1,000 total; max fields per record 2,048; max registered fields per mode 4,096; max key/ID 512 UTF-8 bytes; max individual scalar text 262,144 UTF-8 bytes; max custom mapping/text file 262,144 bytes and 2,048 noncomment bindings.
- Limit violations reject the whole operation, never truncate stored data. View lists are virtualized; field-value previews are 4,096 characters; diagnostics show at most 200 rows plus exact total.
- Name limit is 256 code points; names are exact/case-sensitive, are never paths, and must be nonblank with no NUL/CR/LF/control characters.
- Unknown values are retained inert; corruption, alias conflicts, file revision conflicts and write failures are visible. Do not swallow errors or replace corrupt libraries with defaults.
- Index 31 has no tracked licence: independent behaviour/schema implementation only; no copied code, screenshots, prose or bundled preset JSON assets. Index 30 MIT licence/provenance must be retained.
- Preserve Styles, UiState, Comparison, VAE tools, API payload, hardware metadata and interruption invariants. No external plugin hot-reload capability is implied by Reload preset tools.
- Original indices 203, 221 and 262 remain fully accepted pending work; no `core:presets` IMPLEMENTED promotion and no NA reclassification. One final implementation-wave commit/push by root after evidence; worker checkpoints remain uncommitted for review or in isolated branches for squashing.

## Review Focus

- A user edits the file outside the app after opening the editor: Task 2 must refuse stale overwrite and preserve their bytes/backup.
- A source preset contains duplicate keys, very large integer seeds or malformed UTF-8: Task 1 must reject duplicates/encoding failures and preserve exact valid integers without Double rounding.
- A custom plugin disappears, two controls share a label, or a saved dynamic option is unavailable: Tasks 3/4 must retain source data and show precise skip/fallback diagnostics without targeting the wrong field.
- A user applies a shared default-based preset in Inpaint while another mode has disabled drafts and a queued job: Tasks 4/6 must reset only destination tracked fields and leave other modes, mask pixels and the queued job unchanged.
- Refresh/reload occurs with an invalid editor draft or a close/dispose races file completion: Task 5 must preserve the draft/error, avoid stale UI callbacks and never start or restart the engine.
