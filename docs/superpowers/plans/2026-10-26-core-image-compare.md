## Binding scope and design

The actual source has a single shared image plane with a draggable reveal edge: Horizontal Slider selects left/right vs top/bottom, with opacity of B, Swap, common 0.5–10 zoom and pan. Default left drag moves edge; Shift-left drag pans, Shift-wheel zooms; arrows pan100 screen pixels, +/− adjust zoom0.5, Backspace/Shift0/Insert reset view; buttons zoom±1 and reset. Touch moves edge. Source fits each image independently into a square without distorting it. Native adapts to a responsive shared rectangular viewport, retains each image's aspect ratio, and starts at a useful50% reveal rather than source's hidden-B initial edge. Direction/pair changes reset reveal/opacity; view reset only resets zoom/pan.

Inputs: two manual upload slots plus Compare Upload; img2img/Inpaint and Extras input/output; optional text/icon/off send buttons (source defaultsOff); txt2img current vs result cached when starting next generation. Optional CtrlAlt left/right click on app images sends to A/B, with optional auto-tab (both defaultOff). Native retains those settings in Comparison's expandable Options panel, adds gallery/preview A/B actions and drag/drop/clipboard via existing ImageInput. Settings apply immediately. No foreign-tab/DOM scraping; native ImageViews are read directly without modifying source files. Comparison always offers source pair buttons even if optional send buttons are off.

Infotext: source highlights comma-separated prompt tags not shared by the other image and changed/missing generation parameter values, in red. Native uses existing Infotext parser and TextFlow (no HTML interpretation), preserves tag order/duplicates, marks changed terms with color plus accessible `Changed:` labels, and provides full raw read-only metadata. All input paths including generated/gallery images get the same metadata handling. Missing metadata is explicitly shown.

Source has no export/save control (download buttons explicitly disabled). Native additionally offers explicit flattened PNG export of the visible comparison, with source-over transparency and no misleading single-image generation metadata. Export cannot target either source path or an existing alias/hardlink; original bytes are never changed. No engine protocol, GPU, plugin shim or external dependency needed.

### Independent review repairs

1. Saved preview path associations are cleared when a decoded live frame actually publishes (not when its asynchronous request merely starts), and when preview is cleared. CtrlAlt sends the currently displayed live pixels to a fresh tracked PNG, with no previous saved file's metadata. The manual helper replaces a saved image with an existing real PNG as a live frame, waits for the published image identity, then checks the sent copy's full pixel array and absent metadata.
2. Direct upload/drop/paste/Clear property changes invalidate pending comparison requests. Internal pair commits suppress those edit listeners; stale successes/errors do not overwrite newer drafts or publish half a pair. A real loading state counts all pending decodes and disables redundant Compare upload clicks. The helper deterministically edits or clears the input in the same FX turn as starting a decode, waits for all actual callbacks, and asserts that both the newer draft and prior atomic displayed pair survive.
3. A new pair resets reveal and B opacity while retaining shared zoom/pan, matching source reset(). Explicit Reset view still resets only transform; Swap retains the whole view. Core state regression and native pair-replacement helper assert both invariants.

These regressions were added before fixes. Parent subsequently ran the updated six core tests, three UI-state tests and actual-image helper successfully; evidence and scope are recorded below. Child did not run sbt or GPU work. Diff checks pass; no sampling/engine behavior changed.
