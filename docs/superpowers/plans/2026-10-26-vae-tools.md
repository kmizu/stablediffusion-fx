# VAE Tools implementation plan

**Goal:** Native encode/decode/encode+decode laboratory and generation decode recovery for extension-index 352, `vae_tools`.

**Architecture:** Dedicated native tool tab preserves file bytes/modes instead of passing encoded data through RGB image pickers. A queued `vae_tools` engine request uses the currently selected checkpoint/VAE, scoped diffusers tiling/precision, safe latent containers and explicit optional model downloads. A request-scoped generation decode catcher retains failed final latents as lossless RGBA PNG plus exact safetensors and gives an explicitly labelled cheap preview. No imports from the parent Web UI.

**Source/spec:** https://github.com/light-and-ray/sd-webui-vae-tools at `47fe6db4f3a8f12320c2fa040d0ba542d6325425`. Read Readme.md, all scripts/vae_tools modules and last eight history entries (latest excludes recursive recovery; prior commits add preview failure fallback, generation recovery, tiled VAE). No LICENSE or licence statement in source tree: clean behavioural reimplementation, no copied code/text.

## Acceptance and adaptations

- Three operations; Full/TAESD encode, Full/Approx NN/Approx cheap/TAESD decode. Unsupported encoding approximations use Full with warning, matching source. Full samples a seeded posterior; no diffusion/UNet required. Current selected VAE/checkpoint is used, permitting manual switching between encode/decode. Record model/VAE/family/scale/operation in report and PNG metadata.
- L: big-endian 4-byte safetensors payload length followed by payload in square grayscale PNG, key `tensor`; tensor is diffusion-scaled BCHW. Also accept/export raw .safetensors explicitly. No pickle/torch object deserialization; Approx NN external weight dictionaries use `weights_only=True`.
- RGBA/CMYK: round/clamp [-10,10] into 8-bit four channels, inverse mapping on decode; explicit quantization/clipping statistics. Four channels use one tile, sixteen use row-major 2x2. Safe codec accepts 16-channel data; application model inference remains native SD15/SDXL (no new SD3 claim).
- RGBA PNG; CMYK TIFF or JPEG quality100; L PNG. Strict mode validation prevents accidental RGB conversion. No source overwrite, exact source SHA256, persisted outputs separate from sources. Batch preserves order, per-item status/results, bounded list, interrupt between items. Decode arbitrary saved encoded files, including edited CMYK TIFF/JPEG. Original bytes never rewritten.
- Tiled VAE via native diffusers VAE tiling; scope/restoration and warning that this is not pkuliyi2015's external hook implementation. Native fp32 retry after NaN/Inf with dtype restored. Existing app supports VAE selection in top bar; dedicated tab explains this and refreshes actual model/VAE report.
- Approx cheap is existing native linear projection (latent resolution); Approx NN produces 2x latent resolution, Full/TAESD 8x. Optional TAESD uses madebyollin/taesd or taesdxl safe weights (MIT); Approx NN uses official A1111 release model.pt / vaeapprox-sdxl.pt and safely loads tensor dictionaries, architecture reconstructed from public API. Never download automatically on normal generation/recovery. Root coordinates notices.
- Generation final decode exceptions/NaNs: retain RGBA PNG regardless selected output format and exact latent .safetensors; cheap RGB preview enlarged nearest and marked Broken, warning plus recovery paths in generation result/infotext. No catcher during explicit tool operations (tool errors remain errors). Request-scope restores methods on success/failure. Preview TAESD exceptions fall back to existing cheap projection. Ordinary successful generation must have identical RGB; cancellation is never swallowed.
- Native scrollable responsive controls, multi-file chooser with PNG/JPEG/TIFF/safetensors/all-files, explicit output folder, operation/representation/approximation/seed/tiling/save-format controls; result list, exact metadata report, separate preview for CMYK without changing its saved original. Stable IDs and selected-tab restoration. Plugin capability `vae_tools`, no generation form or invented engine hook.
- MCP explicit tool on local input files uses normal path policy and queue; reports artifacts without converting encoded data. No automatic external sends.

## Independent-review follow-up

- Input hashes stream in 1 MiB chunks inside each item's error scope. Decode file size is rejected before opening/hashing; queued missing/unreadable files produce item errors and later items still run. New RED/GREEN test refuses all Path.read_bytes calls and any oversized-file open, with missing/unreadable/oversized inputs followed by a successful valid input.
- A shared portable PNG provenance object now includes actual selected external VAE/hash (or checkpoint VAE via model), family, scaling factor, optional shift/mean/std, operation/representation/approximation and statistics. Encoded, decoded, display-preview and recovery PNGs carry it. Ordinary exported safetensors also carries this metadata.
- Precision correction: scale and inverse-scale in fp32 before casting into the selected VAE dtype. Critically, exact recovery safetensors stores the **actual failed VAE decoder input** unchanged and tags `sdfx_vae_tools.coordinate=vae_decoder_input`, with configuration provenance. Full decode honors that tag and bypasses scaling. This preserves fp16/fp32 decoder input bits, including the review boundary -7.99609375, instead of claiming the original pre-scaling denoising tensor is still available. The recovered RGBA PNG remains source-compatible `diffusion_scaled`, quantized, and explicitly approximate. Ordinary source L/untagged safetensors continue to mean `diffusion_scaled`; approximate decoding of exact recovery first maps to diffusion coordinates using its saved source scaling configuration.
- New regression captures inputs to an actual tiny VAE decoder after capture/save/reload: **all 10,000 fp16 values and all 10,000 fp32 values compare bit-for-bit**, plus all-mode portable PNG metadata and batch input failures. All six new tests failed before fixes and passed after; Scala unchanged during root compile freeze.
- Additional independent standard-coordinate test builds fp32 diffusion-scaled tensors from 10,000 half values and verifies the actual tiny decoder sees the exact original half bits after inverse scaling. Final changed-code/codec/actual VAE/intermediate-recorder/benchmark CPU checks: **81 passed, 2 existing torchsde warnings in 15.52s**. No GPU/sbt/download execution; git diff --check passed.
