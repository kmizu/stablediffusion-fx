# Native Temporal Coherence Lab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Deliver and verify all user-facing Abysz LAB temporal-frame workflows as a native application workspace for issue #1.

**Architecture:** Independent Python frame processors execute through the existing serial JSON-lines worker; a JavaFX workspace sends typed requests, receives progress, cancels, and displays results. Validated frame sources are immutable and a fresh staged output is committed only on success. The original source is behavior reference, not code to copy.

**Tech Stack:** Python, NumPy, Pillow and the existing `opencv-python-headless==4.11.0.86`; Scala 3/JavaFX; JSON Lines; pytest and MUnit.

**Spec:** `docs/superpowers/specs/2026-10-27-abysz-lab-design.md`.

## Global Constraints

- Preserve all six workflow classes and named controls in the spec; do not declare full completion for a partial subset.
- Upstream GPL-3.0 pin `deff0d4b4a208f862299b14b93e088f613373153`; independent reimplementation, no upstream source copying; the app is AGPL-3.0; resolve license/notice requirements before release.
- ReForge parent is read-only reference, never import or launch it. Process source sequences read-only, never overwrite user data. No shell commands derived from paths.
- User requested core real-model and memory checks rather than exhaustive matrices; real SD1.5 and SDXL generated-frame smoke, visual inspection, core allocation/release observation still required.
- ROOT runs tests, build and real GUI/GPU checks; workers author source/tests only. Use isolated worktrees, integrate reviewed changes explicitly.

## Review Focus

- Input/output overlap via case differences, junctions or symlinks must fail before writing (Task 1 test).
- Failed decode, cancelled processing, full disk or destination race must preserve existing data and remove only own staging (Tasks 1 and 2 tests).
- Empty, corrupt, unequal and mixed-dimension frame sequences must give actionable errors and preserve frame correspondence (Tasks 1–2 tests).
- User submits, closes the workspace or cancels while a job is in flight: no FX blocking, orphan callbacks, unbounded preview memory or incorrect success (Tasks 3–4 tests).
- Unsupported capture FPS or impossible target rate must not silently produce duplicate or empty output; resources must always close (Task 2 tests).
