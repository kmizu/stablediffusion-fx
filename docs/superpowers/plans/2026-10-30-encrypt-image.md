# Image encryption compatibility Implementation Plan

> Use superpowers:executing-plans; one commit for the completed wave.

**Goal:** Integrate the upstream image-scrambling workflow into native SDNUI with accurate security labeling, read compatibility and safe output handling.

**Architecture:** A tested Python compatibility codec reads three upstream formats and writes version 3. Native session state and worker operations must coordinate save and in-memory display, capture queued settings, and keep plaintext exposure explicit. An inventory of all output, metadata, gallery, image transfer, batch, cancellation and package routes precedes integration decisions; do not equate a codec with issue completion.

**Tech Stack:** Scala 3/JavaFX, Python/Pillow/NumPy, JSONL. **Spec:** `docs/superpowers/specs/2026-10-30-encrypt-image-design.md`.

## Global constraints

Pinned upstream AGPL source is reference only; reimplement behavior and retain required notices. Never launch or import parent reForge. LF files; no password logging/persistence; no silent plaintext fallback. One commit per wave, only mark index 237 done after complete acceptance.

## Review focus

Wrong password with/without verifier; Unicode passwords and alpha; legacy variants and uncommon image sizes; queued settings and restart; failed/interrupted writes and unintended plaintext paths. Test each where implemented and inspect actual on-disk output rather than infer safety from UI.
