# Issue 1: Native temporal coherence lab

## Evidence and scope

The source is [Abysz LAB](https://github.com/AbyszOne/Abysz-LAB-Ext) at `deff0d4b4a208f862299b14b93e088f613373153`, GPL-3.0. Its README describes reference-guided differential frame interpolation (DFI), periodic refresh, deghosting, smoothing and source denoise. Its actual `scripts/Abysz_Lab.py` UI additionally exposes DFI map preview, inter-denoise and frame limit; sequential blend, overlay and normalize deflicker; style/video frame fusion; video frame extraction with FPS; and previewing output as video. The source implementation uses grayscale adjacent-reference differences, inverse threshold, expansion and smoothing, then carries prior generated output into stable regions. There is no equivalent temporal-coherence subsystem in the current native app. Existing Stable Video Diffusion and caption features are not this functionality.

This is a proposal for an independently written native implementation, not a claim of byte-for-byte parity. The app is AGPL-3.0: preserve license boundaries, do not copy upstream source, and document upstream attribution and the verified license. Assess applicable license conditions before distribution; behavior-only reimplementation must not be described as copied source. Do not claim completion merely because a generic smoothing filter exists. The UI and operations below cover all upstream user-facing classes, with documented deviations from fragile upstream filenames, process-global working directories and destructive overwrites.

## User flow and operations

Add a native **Temporal Lab** workspace accessible from the main tab list. It accepts local files and directories with folder pickers, shows labeled controls, per-operation progress, cancellation, completion/error details, and the actual output location. Keep long processing off JavaFX's thread. Do not start an operation until settings are validated; disable the operation's own run controls while active and leave unrelated generation state intact.

* **Reference-guided DFI:** choose reference sequence, generated sequence and new output directory. Pair frames in deterministic natural filename order, show both counts and require equal nonzero counts and consistent dimensions; error on ambiguous sequence and missing/corrupt frames. Offer source denoise, tolerance 0.5–20 (default 5), expand 0–50 (default 0), mask smoothing 1–99 odd (default 1), inter-denoise 1–25 (default 9), inter-denoise size 1–25 odd (default 9), frequency 1–15 (default 3), inter-blur 1–5 (default 3), refresh frequency 0–30 (default 0), preserve 0–100 (default 0), and frame limit (0 = all). These are upstream control domains; any practical numerical interpretation differing from upstream must be labeled and justified. A preview selects one reference transition, shows a stability/deghost mask and associated generated pair without writing output; test preview amount behavior or explicitly replace it with deterministic frame selection.
* **Deflicker:** sequence + new output directory; ordered enabled stages of temporal blend strength 0–1, overlay 0–1, and normalize 0/1. All disabled is an explicit copy/no-op. Controls show what each stage does. The overlay stage follows upstream by emitting the first pair composite for both first and second outputs; show this explicitly in the UI rather than implying one-to-one correspondence. Other stages retain frame count.
* **Fuse:** paired style and video sequences, equal counts, output folder and overlay strength 0.1–1 default 0.5. Resize a style frame to its corresponding video frame only with explicit indication; output dimensions follow video.
* **Extract:** local video, output directory, FPS 0 for input or positive requested rate. Decode via existing OpenCV dependency, report duration/FPS and timestamp sampling policy; reject unsupported input, invalid metadata/FPS and corrupt decode. Create deterministic numbered frames; never duplicate samples to pretend a source contains higher FPS.
* **Output preview:** show ordered frames/video playback in-app with play/pause, seek, stop and frame timing, and dispose resources on workspace closure. This should not need ImageMagick or launch an arbitrary shell.

## Safety, integration and limits

Treat model and source inputs as read-only. Never delete, rename or overwrite user inputs or preexisting output. Resolve/compare input/output paths including Windows case and symlinks; disallow overlap and path escapes, reject symlink/reparse output surprises. Stage each job in a fresh uniquely named temporary child of the chosen output parent, then publish only successful complete results to a new nonexisting directory; clean only that job's own staging on error/cancel and report cleanup failure. No shell interpolation. Bounds for dimensions, frame count, total decoded pixels, preview cache and disk use are explicit and validated before allocation; process sequentially rather than keeping video in memory. Close file handles/video capture on every exit. Interrupted operations report interrupted rather than success, and do not publish partial final directories.

Use the existing Python JSON-lines queued worker (`server.py`, `Engine`, `DryRun`, `JobContext`) for work and progress/cancellation. Add a dedicated `temporal_lab` operation with discriminated `operation` (`dfi`, `preview`, `deflicker`, `fuse`, `extract`) and typed, validated params/results; no checkpoint required. A dry-run validates and reports deterministic fake outcomes without importing torch. `Engine.features`, `dryrun.features` and tests must accurately advertise capability; MCP gets a typed safe route or an explicit unsupported policy consistent with local path handling. Classify the dedicated native workspace as `core:temporal-lab` in the extension ledger once accepted, following existing core UI equivalents; do not register an inert sampling plugin. Preserve original index 122 and source attribution. Local file access is user initiated; if exposed through MCP, reuse the existing restrictions on paths and dangerous requests.

## Acceptance

Test actual frame pixels and counts, DFI stability on static vs moving references, each parameter's influence and its bounds, preview/run consistency, ordering/pair mismatch and independent operations. Prove control changes apply to submitted jobs, progress and cancellation, no FX thread blocking, deterministic copy/no-op, input preservation, output collision, concurrent runs and cleanup. Exercise extraction with a small real local video and output playback, plus dry-run without optional ML packages. Real-app verification includes UI screenshots and interaction at usable window sizes; because this task postprocesses frames, use short source/generated frame sequences from both real SD1.5 and SDXL runs, visually inspect source/output and document that as a bounded smoke rather than a quality guarantee. Archive a source pin and original license/notice as appropriate, update the ledger only after acceptance, regenerate docs, and record all evidence and limitations.

## Implementation rulings after source inspection

Each input sequence must be internally dimension-consistent. DFI may take reference and generated sequences with different dimensions: it center-crops and resizes the reference to the generated frame size and shows this adjustment in the UI. Inter-blur is an explicitly documented enhancement: upstream exposes this control but its pinned source does not use its value. The memory guard estimates array scratch usage; a video codec may allocate a decoded frame before Python can inspect its actual dimensions, so it is not a hard process-memory cap. File-system path safeguards assume other processes do not maliciously swap ancestor directories during a job.
