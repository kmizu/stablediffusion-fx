## Approaches and selected proposal

1. **Reuse ExtendedStyle or full UiState snapshots.** Small apparent integration cost, but ExtendedStyle covers six fields and loads models; UiState is a single restart state and whole-VM restore resets unrelated fields. Neither can express tracked fields, two collections, source IDs, or default-based apply. Reject.
2. **Two completely separate implementations.** Closest to each original UI and file shape, but duplicates bounded I/O, field validation and plugin discovery. Fixes can diverge and identical controls become incompatible. Viable but unnecessarily expensive.
3. **One typed field/store/application foundation with two visible profiles. Selected proposal.** A native Settings presets pane offers Config Presets and Preset Utilities. They share field metadata, storage and error UI while keeping collection membership, selected-field rules, apply base and source codecs distinct. Scala 3/JavaFX remain the UI; pure Scala core code owns documents and I/O. No Python hooks, provider, network or added dependency is needed.

## Existing architecture that constrains the design

`GenerationVM` owns individual JavaFX properties including disabled hires and three ControlNet drafts. `toParams` filters unusable ControlNet units; `snapshot` still normalizes hires by mode and strips model fields. Neither is a lossless preset capture. Read properties directly on the FX thread into immutable values. Do not call `GenerationVM.load`: it changes clip skip, all common fields and ControlNet slots, and can add LoRA tags.

`PluginsVM.scriptForms`/`alwaysOnForms`, `PluginValuesVM.props`, and `plugin.controls` are the real schema. Control includes Slider, IntField, Check, Choice, DynamicChoice, Text and ImageFile; Note/Section have `hasValue=false`. Dynamic choices come from existing `CatalogVM` lists and `PluginValuesVM.options`; no service request is required. `PluginRegistry.values` includes saved user settings and is NOT the component-default baseline. Default reset uses a fresh `GenerationVM`'s declared properties and `Control.default`, independently of UiState/settings/current values, except the explicit source Extra=false compatibility default below.

`JobBuilder.build` freezes generation params, script/AlwaysOn Values and submitted payload context. Presets alter the editable form only, never a previously queued Job, inspector snapshot or engine body. MainWindow currently commits focused spinner text before generation; preset save/apply must commit it too. MainWindow's mask export is asynchronous: block preset Apply while `exportGate.isBusy` rather than changing submission timing or altering its captured form mid-export. Ordinary save/view/select-without-apply remains available. Existing capture and queue behavior otherwise stays unchanged.

Native Mode has Txt2Img, Img2Img and Inpaint. Config collections map Txt2Img -> config-txt2img, Img2Img/Inpaint -> config-img2img; apply targets only the invoking mode. Mask fields apply only in Inpaint. Utilities shares one collection across all three, but only the destination's registered fields participate in reset/apply. Hires applies only to Txt2Img. Display the actual destination and collection beside the selector. Changing active tab does not itself apply a preset.

## Fields, identity and compatibility

Native stable field keys are `generation.<property>` (exact GenerationVM property except the logical shared denoising key below), `controlnet.<slot>.<property>` (slots 0..2), `plugin.<plugin-id>.<control-key>`, `script.selected`, and `ui.variationExpanded`. Plugin IDs/control keys are encoded as JSON path segments in the internal `FieldKey` model, not split naively on dots. Printed ID uses percent-encoding for `.`, `%` and control characters in segments; decode must be canonical and round-trip. Built-in descriptors refer to exact properties; plugin descriptors use actual `hasValue` controls and form props, including disabled drafts. Unknown external plugins cannot run code merely by reading a preset; normal app registry loading remains the existing trust boundary. Duplicate plugin/control IDs are exposed as unavailable, not last-wins binding.

`generation.denoisingStrength` is intentionally mode-relative: in Txt2Img it binds `vm.hiresDenoise`; in Img2Img/Inpaint it binds `vm.denoise`. Both profiles use this one logical key for their source denoising controls. This preserves Utilities' shared label semantics when a preset is saved in one mode and applied in another; serializing only `hiresDenoise` would incorrectly skip the img2img value. Do not register competing raw hiresDenoise/denoise keys in the same profile catalog. Source mode determines export ID for Config, while Utilities always exports `Denoising strength`.

Config tracked defaults equal its available standard IDs below. Extra native properties/plugins require explicit selection as tracked fields. Utilities tracked defaults equal its available standard labels; custom fields added through editor/additionalConfigs extend that set. A field being tracked, checked for save, present in a preset, and available in the current mode are four separate facts. The inspector shows them separately. Selecting a saved preset never silently expands the tracked set; imported untracked keys are retained and reported. Import review offers to add mapped keys to tracked fields, with an explicit per-import action.

### Seed Extra is a processing gate, separate from disclosure

Correction to the initial design: source `m_subseed_show` / `Extra` is not merely visibility. Read-only parent reForge at `3b56b268ad9158ee8b30900973b6ccda4ec22241`, `modules/processing_scripts/seed.py:38-77`, declares Extra default false, changes the group's visibility, and its setup forwards subseed/strength only when Extra is true and strength>0; seed-resize additionally needs positive dimensions. `modules/processing.py:255-259` clears subseed/strength/seed-resize when seed_enable_extras is false. Mapping it only to a collapsed TitledPane would wrongly run variation when a saved nonzero strength remains.

Selected minimal native proposal: add `GenerationVM.variationEnabled: SimpleBooleanProperty(true)`. New native UI and old UiState without this field retain their existing always-available variation behavior. Add an explicit checkbox `variation-enabled-<mode>` to the variation section; its expanded/collapsed state remains independent `ui.variationExpanded`. The native label is Enable variation. Source Extra maps to that gate because seed-resize remains an explicitly unsupported separate source field; do not claim a seed-resize implementation. Users may edit disabled subseed/strength drafts; a status hint says the values are retained but not used until enabled.

`GenerationVM.toParams` supplies `subseedStrength = if variationEnabled.get then subseedStrength.get else 0.0`; `subseed` continues carrying its existing draft value. No GenerationParams/JSON Lines/engine/Python schema change is required. Strength zero is the existing no-variation semantic, so generation uses the same seed path as a direct native strength=0 job with that subseed. Retaining the inert subseed avoids introducing a new RNG-resolution condition: existing `Generator.prepare` resolves a negative subseed regardless of strength (`Generator.scala:213`), and this design neither adds nor removes that call. Applying/capturing a preset still consumes no RNG; explicit subsequent Generate follows the existing resolution code. This is native generation equivalence, not byte-identical A1111 effective subseed payloads.

`GenerationVM.snapshot` must explicitly retain raw subseed and raw subseedStrength even while disabled; otherwise the new toParams gate would erase drafts on restart. Add `UiState.variationEnabled: Map[String, Boolean] = Map.empty`, saved per mode. Startup loads raw params then the saved gate, defaulting missing entries to true. No field is added to engine GenerationParams. Existing `load(p, keepImages=false, includeModel=false)` gains final optional parameter `variationEnabledState: Boolean = true`; restoring a plain GenerationParams remains usable regardless of the previous disabled gate, and existing call sites/tests keep their behavior. Startup passes the UiState gate explicitly. Preset field writes do not call load.

PNG/infotext Restore uses the existing Infotext parser values (variation seed/strength absent -> -1/0, unchanged from current behavior), then passes `variationEnabledState=true` when Variation seed or Variation seed strength metadata is present, otherwise false. Thus Restore does not leave a valid variation PNG silently disabled, and a no-variation PNG still restores no variation. Restore is a deliberate whole-parameter operation, unlike preset partial overlay; it may replace variation drafts as it already does. Do not infer gate state from lastSeed, section visibility or model state. Send-to/restore paths need the same test through MainWindow.

Source-profile default for `generation.variationEnabled` is false (the original Extra default), even though a fresh native VM defaults true for backward compatibility. `PresetFieldSpec.defaultValue` for this adapter is therefore false in both profiles; Config always overlays and normally tracks this only when user-added, while Utilities includes Extra by default and unchecked Stackable resets it to false. Inspector must label this as Source preset default=false / Native initial value=true. A preset containing Extra=false only changes the gate, leaving positive draft strength/subseed untouched; selecting Extra=true later recovers them. A preset containing only Variation strength never implicitly enables or disables the gate. UI disclosure is a separate native-only field, with no Extra export alias.

This explicitly revises the earlier assumption that GenerationVM, UiState and GenerationPanel need no semantic change: the finite gate, raw restart snapshot and restore admission are necessary source compatibility work. The approved diagnostic-context exception below also changes JobBuilder and the Scala payload-context formatter; Generator and the engine request/protocol stay unchanged. API inspector body shows effective strength zero for an ordinary submitted disabled job; raw draft strength belongs only to preset/UiState inspection, not an invented engine body. Existing queued jobs and captured payloads remain immutable when the gate changes later. The cost is one UI property, one optional UiState map, a small form checkbox, one immutable optional diagnostic-context flag and boundary/restore tests; a visibility-only adapter or zeroing editable strength is not an acceptable shortcut.

Approved root ruling: append `uiVariationEnabled: Option[Boolean] = None` as the final field of `SubmittedPayloadContext` in `core/.../payload/RequestPayload.scala`. At actual UI submission, JobBuilder freezes `Some(vm.variationEnabled.get)` into the Job's context; non-UI/legacy callers retain None. `PayloadCaptureContext.document` emits `submitted.ui_variation_enabled` as boolean or JSON null. This records the real submitted checkbox independently of `requested_seed_options.extras_requested`, whose existing formula remains `(p.subseed != -1 || p.subseedStrength != 0)` and now carries `extras_requested_basis="native_params_inference"`. Never replace that inference with the UI flag: a script can change strength after a UI gate=false submission, and even disabled positive-subseed drafts make the existing inference true. Context and effective request can truthfully differ. The flag is immutable Job data, not a hidden store cache; serialization counts its bytes/nodes under existing payload budgets. No GenerationParams, exact body, protocol, Generator, kernel, RNG or Python change is authorized by this exception.

Variation execution boundary: current `python/sdfx/engine.py:1223-1224` warns `variation seed is only applied in txt2img` for positive img2img strength. Gate controls, draft persistence and zero/positive parameter submission are covered in all three native modes, but this wave adds no img2img/Inpaint variation kernel. Actual SD1.5/SDXL variation-effect checks therefore use txt2img: disabled positive drafts match a direct strength-zero baseline, and re-enabled drafts match the corresponding positive-strength baseline. Img2Img/Inpaint tests assert control/submission behavior and preserve the existing limitation/warning; GenerationParams or body parity is not evidence of variation affecting those images. No original source obligation is reclassified or promoted on that limitation.

## Data format and storage contract

Default authoritative path: `AppHome.configDir/native-presets/library-v1.json`. `--configpresets-dir <existing-directory>` moves this one authoritative file (including tracked-field and mapping sections); no hidden fallback. Directory selection is independent of image/output directories. Native v1 envelope: `format="sdfx-native-presets"`, `version=1`, `collections` array. Each collection has `id` (`config-txt2img`, `config-img2img`, `utilities`), `tracked` field keys, `bindings` declarative source aliases, and ordered `presets`. Record: `id` UUID, `name`, `fields` keyed by canonical IDs with typed scalar string representations, `source` (format, original name, original mode, exact original raw field-object JSON), `dirty` canonical field-key set, and `opaque` exact raw unresolved source entries. Import starts with empty dirty set; modifying a canonical field adds it to dirty, removing a saved known field does likewise. This provenance is required to re-export untouched known aliases with their original values/number representations, not only unknown fields. Preserve unrecognized envelope/collection/record properties as bounded raw JSON and write them back unchanged semantically; preserve unknown numeric lexemes exactly. Reader must not pass source seed numbers through Double. Numeric JSON uses a lexical BigDecimal/Long conversion; exponent-integral -1.0 is accepted as -1, overflow/fraction is rejected for integer fields. Unknown values are inert raw JSON, never executable metadata.

Identity first uses the unchanged core initialId(collection, name), UUID.nameUUIDFromBytes over UTF-8 collection ID + NUL + exact name. The stored UUID remains stable on overwrite and survives order changes/external name edits. If another renamed record occupies that first candidate, Task4's private controller creation policy tries deterministic collection + name + salt-counter candidates within a fixed bounded attempt limit; it never uses RNG or changes existing IDs. Saving a free valid name must succeed when an alternate is available; duplicate-ID failure is allowed only after exhausting that bounded policy. Regression: rename A to B retaining UUID A, then create A successfully with a different stable ID; repeat overwrite retains each ID. Duplicate UUIDs or duplicate exact names already present within one collection still reject the file; same name in different collections is valid. Names are case-sensitive, preserved without Unicode normalization or trimming; require at least one non-whitespace code point, at most 256 code points, and no NUL/CR/LF/control characters. Names never enter a filesystem path. Repeated source imports of the same name require the import review's Overwrite or Skip action; default is Skip. Explicit same-name Save is overwrite and clearly labelled before the click. Deleting the final entry yields a healthy empty collection and disabled Apply.

Bounds are exact: per file 4,194,304 UTF-8 bytes; max JSON nesting 32; max lexical nodes including keys 100,000; max collections 3; max records 1,000 total; max fields per record 2,048; max registered fields per mode 4,096; max key/ID 512 UTF-8 bytes; max individual scalar text 262,144 UTF-8 bytes; max custom mapping/text file 262,144 bytes and 2,048 noncomment bindings. Limit violations reject the whole operation, never truncate stored data. View lists are virtualized; field-value previews are 4,096 characters with explicit truncation labels; exact export remains available within file limits. Diagnostics show at most 200 rows plus exact total, with bounded downloadable report.

Read with bounded streams (limit+1), strict UTF-8 decoder, lexical depth/node/duplicate-key checks before constructing values; reject malformed JSON, duplicate keys at any nesting, nonfinite numbers, unpaired surrogates and unsupported format versions. `PayloadJsonBudget` supplies useful budget primitives but does not detect duplicates or preserve numeric lexemes: do not use ordinary ujson.Obj parsing alone as this reader. New `PresetJson` owns strict lexical reading and exact numeric tokens; use project-local Scala/JDK and existing upickle only. Fixtures are independently authored, not copied unlicensed assets.

Writes: serialized on one preset I/O executor; bound/validate complete next bytes before touching disk. The UI admits one library mutation at a time, sets its pending gate before scheduling and rejects overlapping save/delete/import/restore/reload with visible Busy while retaining user drafts. Every save carries its caller's expected library revision, not merely the session's latest revision; install the successful revision before reopening mutation controls. This prevents a second stale whole-library candidate from erasing the first save even though disk writes are serialized. Obtain a cooperating-process lock on `.library-v1.lock`; compare SHA-256 of current disk bytes to the expected loaded revision (including the missing-file sentinel); if changed, return Conflict and retain drafts. Write a same-directory temp with CREATE_NEW, flush with FileChannel.force(true), copy previous good bytes to `library-v1.json.bak` atomically, then ATOMIC_MOVE/REPLACE_EXISTING to target. If atomic replacement is unsupported, report failure and leave original intact; no destructive fallback. Keep one backup, never rotate a corrupt file over the good backup. Authoritative filesystem paths must remain inside the resolved configured directory; refuse symlink/reparse-backed target/lock/backup paths and refuse directory substitution detected before commit. External editors not honoring locks still have a final compare-to-move race: document this limitation, recheck immediately before replace, preserve backup, and never claim transactional isolation from arbitrary tools.

Load/refresh failure retains the last good in-memory document as read-only, records exact path/reason and blocks mutation until a successful explicit reload or explicit restore-backup operation. Do not replace a corrupt existing library with defaults. A missing library at first-ever start may be seeded; a library disappearing after a successful load is a conflict, not permission to reset. Restore-backup previews its revision and saves the corrupt bytes as `.rejected-<UTC timestamp>.json` only on the explicit Restore action; failure to preserve those bytes aborts restoration. The app never auto-deletes user data. Unknown fields survive overwrite of a known record unless the user explicitly removes them in the field editor; ordinary save updates selected known fields and preserves opaque entries, with removal of deselected previously saved known fields described in the overwrite preview.

Source export keeps source dictionary shape (name -> field object) with original keys/values for untouched entries; changed known fields use canonical source keys and typed values. Alias conflicts and unknown fields remain represented. Export cannot silently omit unknown data, native-only fields or two canonical fields colliding on one source key: fail with exact offending keys unless the user explicitly chooses a separately labelled Supported fields only export. Native full export is always lossless within limits. UTF-8 whitespace/key ordering need not match source bytes; archive original imported bytes+hash in the operation report, and preserve raw opaque numeric values. No claim of binary byte-for-byte source roundtrip.
