## Approaches and proposed choice

1. Enrich every existing picker with image rows. Compact, but broadens the generic SearchPopup API, cannot expose embeddings or other network folders alone, and entangles preview work with quick selection.
2. **Proposed: one shared native Models / Networks browser, reusable virtualized preview card component, independent local presentation catalog.** Keep quick pickers intact and add explicit browse entry points. One resolver/policy/loader serves all kinds and windows. This adds a real surface and keeps generation authority with existing services.
3. A gallery filter or a checkpoint-only demo is rejected: generated gallery is the wrong source surface; model-path matching, synthetic-only cards or type-restricted policy would not fulfill the extension.

ROOT must review the following proposed decisions as a coherent whole: local-only preview source URI definition; sidecar order plus explicit override; separate presentation scan; generic inspect-only roots; one process/AppServices-scoped temporary policy; native blur approximation and deliberate keyboard reveal; checked persistence; budgets and release gates. No code should be derived from this draft until that review approves the spec and plan.

## Proposed architecture and exact contracts

Use Scala 3.3.6 / JavaFX 21.0.6 and Java 21 for native acceptance, existing uPickle/munit and JDK ImageIO. Python protocol and generation models stay unchanged. Names below are planned interfaces, not existing APIs.

### Pure preview identity and policy (`core/.../modelcards/`)

`CardId(kind: String, modelPath: String)` uses a nonempty kind and absolute normalized model path. Stable storage key is the JSON array `[kind, modelPath]` serialized compactly, avoiding delimiter collisions. Preserve path spelling for display; canonical real path is only for deduplication/access checks. On Windows comparison of canonical identities follows filesystem case behavior; source URI matching never uses the model identity.

`PreviewReference(localPath: Path, source: String, identity: LocalPreviewIdentity, allowedRealParent: Option[Path])` is constructed only by a validated resolver. `source` is exactly the validated selected `localPath.toAbsolutePath.normalize.toUri.toASCIIString`, recorded once and used as the visible preview source. Use that URI as loader provenance, although the decoder reads a bounded validated file snapshot. Do not decode URL escapes, inspect model path/tags, or rebuild source from a thumbnail cache key. Examples: model under `nsfw/` with explicit safe preview elsewhere does not match; safe model with `NSFW-preview.png` does. None allowedRealParent denotes explicit chosen preview, Some binds automatic resolution to its approved parent.

`enum CardPreviewMode { Blur, Hide, Show }` and `CardPreviewPolicy.matches(source: Option[String]): Boolean`; `CardPreviewPolicy.startup(saved: String): CardPreviewMode` accepts exact case-sensitive mode strings, invalid/null -> Hide. `CardPreviewPolicy.presentation(source: Option[String], mode: CardPreviewMode, revealed: Boolean): PreviewPresentation` returns `Normal`, `Blurred` or `Hidden`; missing source never triggers a matched-image rule. `Blurred` -> radius20; Hover/intentional keyboard reveal only has effect in Blur. Hidden never decodes/reveals on hover. No per-card persistence.

### Persistent configuration and runtime state

Add `Settings.nsfwCardBlurDefault: String = "Blur"`, JSON `nsfw_card_blur_default`; `modelPreviewOverrides: Map[String,String] = Map.empty` (CardId key -> absolute local preview path), JSON `model_preview_overrides`; `modelPreviewFolders: Map[String,Seq[String]] = Map.empty`, JSON `model_preview_folders` (additional inspect-only kind -> model directories). Existing `ModelDirs` remains inference configuration. UI labels explicitly distinguish additional preview folders from supported inference types.

Missing field in a valid older file uses Blur. An existing invalid/null/wrong-typed mode is normalized to Hide *before* the Settings decoder, so one bad field does not erase other settings. Missing settings file is a fresh installation (Blur). Whole-file malformed/unreadable/null settings use recovery with the new policy forced Hide. `Settings.loadResult(file): SettingsLoadResult` returns settings plus `recovery: Option[SettingsRecovery]` (reason and optional original-file SHA-256); `Settings.load` remains a compatibility wrapper, but production UI/MCP entry points must pass the load result's provenance to AppServices, preserving it through VRAM normalization/bootstrap. Recovery metadata is not Settings JSON. Any field recovery also sets this hold, so invalid new maps are not silently erased on shutdown.

AppServices owns `settingsRecovery: Option[SettingsRecovery]` and suppresses **all automatic persistence** while held: model/VAE remembering, plugin values, normal close/shutdown, MCP and bootstrap configuration paths included. Legacy `updateSettings` may still successfully update memory, logs persistence-held once, and must not write the failed-load file. Ordinary checked explicit edits return a recovery-required error while held; Settings UI exposes a clear “Save recovered settings” action showing the original load problem. Only that deliberate recovery save can atomically replace the file and clear the hold; write failure leaves both hold and original bytes intact. This is a product save action, not an agent approval round. `persistSettings=false` never clears a recovery hold by pretending a disk write succeeded. SdfxApp's existing direct UsePython save must route through the owned persistence decision (or carry the updated in-memory load result until services exist); no bootstrap or shutdown bypass.

Admit at most16MiB of UTF-8 settings input before JSON parsing, reading through a bounded stream rather than `readString` followed by a size check. New preview configuration collectively permits10,000 overrides,8,192 characters per path/key,64 kind names (max128 characters),256 roots (max8,192 characters), **1,000,000 total UTF-16 code units and4MiB total UTF-8 serialized bytes** across both maps. Count keys and values plus encoding overhead before accepting or serializing new entries; stop parsing/admission with visible recovery diagnostics when exceeded, retain unrelated valid fields when within whole-document parser limit, and preserve original bytes under hold. Individual caps do not authorize allocating their full Cartesian maximum. In-memory normal saves must satisfy the same aggregate bounds before creating duplicate serialized maps.

`AppServices.updateSettingsChecked(f: Settings => Settings, intent: SettingsSaveIntent = Explicit): Either[String,Settings]`, with intent `Explicit | Recover`, synchronizes with existing settings updates, computes from current memory, validates caps, saves before assigning `_settings`, and clears recovery only after a successful Recover disk write. Explicit is rejected under hold; Recover without a hold is an ordinary explicit save. In persistSettings=false tests ordinary non-recovery checked updates may update memory, but Recover returns failure. No unlocked read-modify-write. Saving only the three new fields preserves current lastModel, pluginValues and unrelated edits; dialog merge copies default/folders but not concurrently changed overrides. Failure never shows “Settings saved”. Atomic-move failure is a failure, without a silent non-atomic fallback.

`CardPreviewSession` lives once on AppServices, contains mode initially Hide then initializes once from loaded settings, exposes `current`, `setTemporary(mode)`, `addListener(mode => Unit): () => Unit`. No JavaFX dependency in engine. All UiContexts/windows sharing services observe it; no per-tab reset, persistence or queue event. A later settings save changes the next-session default only; “Use saved default now” is an explicit temporary action. New AppServices/session starts from saved default. A new window sharing the existing services inherits current temporary mode.

### Local presentation catalog and reference resolution

`ModelCardRecord(id: CardId, name: String, family: Option[String], preview: Option[PreviewReference], problem: Option[String])` is presentation data, never serialized into GenerationParams or engine requests. `ModelCardCatalog` consumes `AppHome`, current Settings and an optional already-cached `CatalogSnapshot`; it must operate with a stopped/unavailable engine. Existing engine metadata enriches kind/family but cannot trigger model IO. A stale engine snapshot cannot authorize an action on a disappeared file.

Read current configured model directories using a Scala filesystem scan; do not launch Python just to browse. Eligible checkpoint files: `.safetensors`, `.ckpt`; other existing kinds and generic inspect-only kinds: `.safetensors`, `.pt`, `.pth`, `.ckpt`, `.bin`, `.patch`. Match extensions case insensitively. Do not read tensor data or detect family by loading weights; family may be unknown. Existing directory model markers are ControlNet `config.json`, SVD and Zero123 `model_index.json`; treat such directories as one entry and do not descend into their weights. A generic root may use `model_index.json` as a directory-model boundary. Do not claim this makes it inferable. Include registered catalog entries for other future kinds through a generic adapter and the same policy; never hard-code policy to checkpoint/LoRA only. Generic roots allow a real hypernetwork card to be inspected now while hypernetwork inference remains a separate todo target.

Resolve previews in this order (agent adaptation, not upstream behavior): explicit override if configured; for a file model, sibling `<stem>.preview.png`, `.preview.jpg`, `.preview.jpeg`, then `<stem>.png`, `.jpg`, `.jpeg`, then `.preview.gif`, `.gif`, `.preview.bmp`, `.bmp`; for a directory model, `preview.png`, `preview.jpg`, `preview.jpeg`, `preview.gif`, `preview.bmp`. Match candidate filename case insensitively on Windows, retain actual chosen spelling. Ambiguous case-only files on a case-sensitive directory produce a problem instead of nondeterministic selection. Override means authoritative: if missing/unreadable it stays unavailable; do not unexpectedly fall back to another image. A Choose preview file action accepts local supported formats anywhere the user explicitly selects, and Remove override returns to automatic resolution. Neither action copies/moves/renames/rewrites source files. GIF is first-frame-only with a visible format hint. Unsupported format is reported rather than downloaded or transcoded. Source has no codec guarantee; these supported native codecs are a disclosed adaptation.

No recursive image search or network preview source. On Windows accept only ordinary fully qualified drive paths (`C:\folder\file`) for explicit previews; reject drive-relative `C:foo`, root-relative `\foo`, UNC `\\server\share`, extended/device namespaces (`\\?\`, `\\.\`, extended UNC), URI strings and unknown drive types. Model roots may be plain relative paths resolved against AppHome, but never drive-relative/root-relative paths. Before traversing/probing a drive, classify its root with a bounded fixed PowerShell/.NET `System.IO.DriveInfo.DriveType` probe: accept Fixed/Removable/Ram only, reject Network (including mapped drives), Unknown/NoRootDirectory and unavailable probes. Use structured stdin JSON with a fixed script, never interpolate paths into command text; max one probe worker, timeout2s/drive, cached only within one scan/open validation. Revalidate resolved drive type for explicit links. This is a local OS probe, not an inference subprocess or new dependency.

Explicit selected local links/root links may be resolved once, retaining their selected URI as policy source; scans never descend through child reparse points. Capture `LocalPreviewIdentity(realPath, fileKey, size, modifiedMillis, ancestorKeys)` for the real file and all selected/resolved ancestors, including reparse target identity. `PreviewReference` carries that validated identity in addition to selected path/source. Automatic candidates must remain inside their approved real parent/directory. Missing fileKey, unavailable ancestor/reparse information, containment change or ambiguous identity means unavailable preview, not an unchecked decode.

Before decode, repeat local-drive, ancestor, link-target and containment validation off FX. Open the captured real path with final-component NOFOLLOW_LINKS, recheck identity around that open, read at most32MiB once into the admitted source buffer, then validate selected/resolved chain again. Reject changes even if size/mtime match; compute SHA-256 from this immutable bounded buffer, use `(fileKey, digest, requestedSize)` for thumbnail identity, and decode only that buffer (no second path open by ImageIO). Cached thumbnail reuse still requires current bounded source snapshot/digest validation. This detects observable same-size/time replacements and ancestor retargets; it does not assert atomic path traversal under hostile concurrent junction mutation. Java/Windows cannot guarantee race-free ancestor binding or zero network IO under adversarial mutation with these APIs; reject observed ambiguity, retain this residual TOCTOU limit in reports and never replace the selected URI with the resolved path for policy matching. Case-insensitive substring rules may intentionally false-match benign filenames.

### Bounded asynchronous work

ROOT platform clarification (2026-10-27): the250ms check is a cooperative active-work bound, not a promise that Java directory/metadata IO can be forcibly interrupted. Check cancellation before and after each potentially blocking operation. Closing or superseding a request invalidates publication immediately and returns without joining the worker; that worker and its reservations remain counted until actual completion. Keep the native probe's2s caller deadline and one actual process/worker owner. Instrument blocking-call duration and cancellation-check gaps, report them separately from active-work checks, and preserve late-result rejection. Do not hide application CPU-loop violations as platform blocking, create replacement workers for blocked IO, or claim a hard250ms wall-clock scan deadline.

One dedicated scan worker, at most one active and one replacement request. Latest revision wins; closing/changing roots cancels older work. Each cooperative scan slice visits at most5,000 entries or250ms of active work between cancellation/yield checks; retained metadata max50,000 cards, depth32, pending directories10,000. A streaming DirectoryStream admits at most4,096 entries and1MiB UTF-16 path/name characters per directory before sorting; stop before collecting more, report partial, close its stream. Global live metadata (old/new snapshot, pending dirs, errors, search strings and indexes combined) permits at most2,000,000 UTF-16 code units and96MiB conservative reservation (128 bytes/object plus2 bytes/character; count copies separately) before materialization; admit records/index entries incrementally and release old snapshots. Fixed error strings cap at512 characters/100 details plus total count. At any cap report partial with reason and “Choose a narrower folder”; no silent full-catalog claim. No filesystem scan, hashing or decode on FX. Reservations bound app-owned structures, not exact JVM object layout; process/heap measurements below must also pass.

`PreviewImageLoader` leases use **one process-lifetime admission/executor owner**, never a new pool per reopen. Two workers total and at most two admitted source buffers (32MiB each), max32 pending distinct keys. Last lease closes its generation nonblockingly: cancel queued work, clear delivery/cache ownership, invalidate tokens, but retain the global owner and count blocked workers/buffers until their work actually exits and releases them. Later acquisition creates a logical generation on the same owner; available worker permits alone admit new decode. Two blocked old workers mean zero new decode until release, showing “Preview workers busy”. Final process shutdown requests shutdown; no replacement pool can be made while old workers remain alive. Interrupt is not proof of termination. No UI-thread join or synchronous decoder close.

App-owned thumbnail pixels are globally capped at32MiB/128 distinct allocations **across cache, visible ImageViews, conversion copies and completed-but-undelivered results**, with reference-counted ownership reservations made before allocation and no eviction of a pinned allocation to evade accounting. A single coalesced FX drain callback serves at most8 completed results/8MiB (included in32MiB); replacement/cancellation drops stale results, full mailbox rejects/drops an unneeded completion and releases ownership. Workers cannot create unbounded runLater closures. Max32 visible preview consumers across windows; extra visible cards show a transient capacity state and retry on release. No persistent cache or original-image cache; only successful thumbnails, error memoization128 keys/generation. Decode only visible and not Hide-matched cards. Read32MiB max source, reject >32MP or side>16,384 before decode, subsample to512px longest side, first GIF frame only. A32MP packed ARGB raster alone is about122MiB; codec temporary buffers, source sample depth and JavaFX native textures can exceed that, so it is **not** a proven total codec bound. Required empirical gates must cover these peaks.

`request(ref, edge, complete): PreviewTicket` returns immediately; bounded completion handoff checks identity, token, revision and generation before attaching pixels. `cancel()`/lease close release queued/delivered ownership and abandon late results, not active worker permits until actual completion. Recycled cells reset image/effect/animation/reveal/listeners. This is not a decoder security sandbox or hard wall-time guarantee. Budget refusal keeps labels/actions alive and a visible reason; do not loop automatic retries while old work is stuck.

Combined preview envelope: at most16MiB settings input,4MiB new-field encoding/1M characters,96MiB metadata reservation,64MiB active encoded source buffers,32MiB globally owned thumbnail allocations,8MiB mailbox within that32, plus **planning headroom** of512MiB for codec transients and128MiB for FX/native preview overhead. The headroom is not a separately enforced/measured allocation claim. Parser/runtime overhead is included in measured process totals, not inferred from these sums. Total incremental helper working-set peak versus same-process pre-browser baseline must be <=1GiB; total helper managed heap <=2GiB configured max and helper private bytes/working set each<=3GiB. Allocation-limit breach aborts admission with a diagnostic; measured-envelope breach fails acceptance and requires investigation/reduction of limits before promotion. Do not claim Java enforces a per-codec native-memory ceiling.

ROOT's current hardware fact is64GiB host RAM, RTX3090 with24GiB VRAM, replacing HANDOFF's old free-memory snapshot. Run one helper/one inference Python worker at a time. sbt host `-Xmx1536m` max; forked helper `-Xmx2g` max, verified via jcmd VM.flags for both PIDs and helper Runtime.maxMemory rather than assumed from build.sbt Compile/run. Sample every250ms with a separate bounded PowerShell observer: Windows Process WorkingSet64 and PrivateMemorySize64 per PID (sbt/helper/Python descendants/observer); helper MemoryMXBean heap/nonheap current + MemoryPoolMXBean peaks; `nvidia-smi` **device-total** memory.used. Thresholds: sbt working/private<=3GiB; observer<=512MiB; Python descendant sum working/private<=32GiB; combined tracked working/private sums<=40GiB; host available physical>=8GiB; GPU device-total peak<=22GiB (2GiB reserve). Record baselines/deltas/timestamps/maxima; gap>2s during active checks fails required measurement. WDDM per-process GPU allocations may be unavailable: record unmeasured, never fabricate them; required device-total/PID/heap/host metrics missing or over threshold fail. Native texture/codec-specific allocation separation is optional/unmeasured and bounded indirectly by process delta/device total, not independently measured. Sampling misses possible sub250ms peaks: retain JVM pool peaks and OS peak-working-set counters where available, disclose private/GPU sampled-peak limits.
