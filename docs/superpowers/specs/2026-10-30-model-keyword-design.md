# Model Keyword design (#85)

Reproduce the pinned `mix1009/model-keyword` behavior for txt2img and img2img, including model and LoRA mappings, textual inversion, per-image choices, mapping management and effective prompt provenance. Retain its MIT license and verify independent provenance and rights for both mapping databases before distribution. The LoRA corpus was removed after evidence of Civitai-derived content was found; a compliant full-coverage approach remains unresolved. User mappings remain separate and editable. Upstream source is reference behavior; preserve observed differences in verification evidence.

Upstream hashes 64 KiB from offset 0x100000, truncating SHA-256 to eight hex digits. Match colliding rows by filename similarity, choosing the later entry on ties. Preserve CSV quoting, pipe-separated keywords, all four placement modes, TI and LoRA ordering, per-image iteration/random choices and selected LoRA weight. A real per-image prompt path is needed: `Plugin.process` runs once per generation request, including multi-image batches. Do not silently reduce scope to one prompt per batch or restrict scripts.

Alternatives considered: mutate the single prompt in an AlwaysOn plugin (cannot represent batch choices); split every image into a separate generation (alters batch semantics, progress and compatibility); extend the generation pipeline to support per-image effective prompts while preserving seeds and metadata. The third is the target; any necessary pipeline change must be tested on SD1.5/SDXL, Hires, scripts, cancellation and Restore. Native controls must expose custom checkpoint/LoRA mapping management, dynamic choices and status without blocking the JavaFX thread.

Protect inputs and mapping files from overwrite, avoid unvalidated downloads and do not mark the ledger done until source and data licences, full real-model/native tests, image inspection and package acceptance are verified. Integration must later account for #48 protected sessions when this worktree is reconciled with main.
